# YOLO 기반 신호등 인식 작업 계획 (미구현, 2026-08-19)

**상태: 검토 단계, 코드 없음.** 카톡 공유 실차 캡처(`20260818_164316`, 156장) 확인 후
결정한 방향 정리. 현재 `perception/traffic_signal.py`(HSV/Hough/FRST 기반 고전 CV)를
전면 교체하지 않고, **하이브리드**로 간다 — 신호등 배경판(rig) "위치" 탐지만 YOLO로
바꾸고, 점등 색상 판정(빨강/초록/좌회전)은 기존 `circle_brightness()`/`shape_ok()`/
`pick_best_4()` 로직을 그대로 재사용한다. 이유: 공유받은 캡처들이 실제로 천장 형광등,
벽 TV/모니터, 역광 창문이 뒤섞인 환경이라 지금 코드가 반복 실패하는 조건과 정확히
겹침 — `_board_candidates()`(HSV 임계값 기반 배경판 탐색)가 가장 취약한 지점이고,
점등 판정(밝기 비교)은 이미 여러 차례 실차 검증된 상태라 굳이 버릴 이유가 없음.

## 참고할 기존 구조

`perception/yolo_cone.py`(라바콘 검출)가 이미 이 저장소에서 동일한 패턴으로 동작
중 — 그대로 템플릿으로 쓸 수 있음:
- `yolo_ros/yolov8n.pt`(COCO 사전학습) → Colab에서 파인튜닝 → `model.export(format='onnx',
  imgsz=640, opset=12, simplify=True, nms=True)`
- `YoloConeEngine`(ONNX Runtime 세션, CUDA/CPU provider) + `YoloConeDetector`(별도
  데몬 스레드, 논블로킹 `detect()`) 2단 구조
- `config.py`에 `YOLO_CONE_INPUT_SIZE`/`YOLO_CONE_CONF_THRESHOLD`/`YOLO_CONE_MODEL_PATH`
  형태로 튜닝값 분리

## 필요한 것

1. **학습 데이터**
   - 라벨링 대상: 1클래스 `signal_board`(배경판 bbox)만으로 시작 — 4개 램프 개별
     클래스까지 가면 라벨링 비용이 확 늘고, 점등 판정은 어차피 기존 밝기비교 로직이
     맡으므로 불필요.
   - 지금 있는 156장(한 세션, 한 위치/조명)만으로는 부족 — 각도/거리/조도가 다른
     세션이 최소 2~3회 더 필요(다른 시간대, 커튼/조명 on-off, S0/S2 두 위치 각각).
     목표 수량 대략 400~600장(음성 샘플: 신호등 없이 형광등/TV만 있는 프레임도
     일부 섞어야 오탐 억제에 도움됨).
2. **라벨링 툴** — Roboflow(웹, 무료 티어로 충분한 규모) 또는 CVAT/LabelImg 중 택1.
   bbox 하나만 그리면 되므로 툴 자체 러닝커브는 크지 않음.
3. **학습 환경** — Colab(cone 모델도 여기서 학습한 전례 있음), GPU 필요.
4. **ONNX 변환/통합 코드**
   - `perception/yolo_signal.py` 신규 작성(`yolo_cone.py` 구조 복사 후 신호등용으로 수정)
   - `traffic_signal.py`의 `_board_candidates()` 자리를 YOLO bbox 리스트로 교체
     (`detect_s2()` 이후 원 4개 판정 로직은 무수정)
   - `config.py`에 `YOLO_SIGNAL_INPUT_SIZE`/`YOLO_SIGNAL_CONF_THRESHOLD`/
     `YOLO_SIGNAL_MODEL_PATH` 등 추가
5. **실차 테스트/튜닝 세션** — 최소 2~3회(초기 동작 확인 1회 + 오탐/미탐 케이스로
   conf 임계값 재조정 1~2회).

## 예상 소요 시간

실제 데이터 촬영·라벨링·실차 접근성에 크게 좌우돼 폭이 넓다. 순수 작업시간 기준
추정치(캘린더 기준 아님 — 촬영/실차 스케줄 잡는 대기시간은 별도):

| 단계 | 예상 시간 |
|---|---|
| 추가 촬영(2~3세션) | 세션당 30분~1시간 |
| 라벨링(400~600장, bbox 1개/장) | 3~5시간(Roboflow 기준 장당 20~30초) |
| Colab 학습 + 반복 튜닝 | 2~4시간(학습 자체는 수십 분, 결과 확인하며 2~3회 반복) |
| `yolo_signal.py` + `traffic_signal.py` 통합 코드 작성 | 반나절(3~4시간) |
| 실차 테스트/튜닝 | 세션당 1~2시간 × 2~3회 |

**총합(순수 작업시간): 대략 2~3일 분량.** 실제 캘린더 기준으로는 실차/장비 접근
가능 시점에 따라 1~2주까지 늘어날 수 있음 — 이 저장소 관례상(README §들 참고)
"실차 미검증"인 채로는 완료로 보지 않으므로, 실차 테스트 세션 확보가 병목이 될
가능성이 가장 큼.

## 리스크/불확실 요소

- **Jetson 자원 경합**: 이미 `dl_lane`(TwinLiteNet) + `yolo_cone`(YOLOv8n) 두 모델이
  동시 추론 중. 세 번째 모델을 얹으면 전체 FPS가 떨어질 수 있음 — 신호등은 S0/S2
  구간에서만 필요하므로 그 구간에서만 추론을 켜는 등 자원 관리가 필요할 수 있음.
  (`yolo_cone.py`가 TensorRT 대신 CUDA로 폴백한 것도 비슷한 자원/호환성 이슈 사례.)
- **음성 샘플 부족 시 오탐**: 신호등 없는 프레임(형광등/TV만 있는)을 학습 데이터에
  충분히 안 섞으면 지금과 똑같이 형광등/TV를 신호등으로 오인할 수 있음.
- **조명 다양성**: 156장이 한 세션·한 조명 조건뿐이라, 이것만으로 학습하면 그
  조건에서만 잘 되고 다른 시간대/조명에서 다시 실패할 위험(현재 고전 CV 방식이
  겪는 문제와 근본적으로 같은 리스크 — 데이터만 다양하면 YOLO는 일반화가 낫지만,
  데이터가 안 다양하면 YOLO도 마찬가지로 취약함).
