# `measure_pixels_per_meter.py` — `DL_PIXELS_PER_METER` 재검증 도구

**상태: 2026-08-15 작성, 아직 실차 미실행.** `local_costmap_proposal.md` 선행작업
4순위(선택, 없어도 다른 작업 착수는 가능). config.py에 반복적으로 "설계값(실측
아님)"이라고 적혀있는 `DL_PIXELS_PER_METER=200.0`을 실제로 재보는 도구.

## 왜 필요한가

`DL_PIXELS_PER_METER`는 실측이 아니라 "BEV 목적 캔버스를 1m=200px로 만들자"고
**그냥 고른** 숫자다. 이 값이 `_apply_vehicle_margin()`(안전마진 침식 반경),
`PASS_OFFSET`, `PP_WHEELBASE_PX` 등 여러 곳에서 "1px가 실제로 몇 m인지"의
근거로 쓰이는데, 실제로 맞는지 한 번도 검증된 적이 없다.

## 왜 근거리에서는 오차가 잘 안 보이는지 (읽어볼 것)

BEV 호모그래피는 실측 캘리브레이션 사각형(가로 0.8m×세로 1.0m, README §6.3)을
"0.8×PPM × 1.0×PPM" px 크기의 목적 사각형으로 매핑해서 만든다. 그 사각형
**안**(=캘리브레이션한 근거리 ~1m까지)에서는 변환→역변환에 쓰는 PPM이 서로
상쇄돼서, PPM이 얼마든 근거리 결과는 이미 자체 일관적(self-consistent)이다 —
그래서 근거리에서만 재면 오차가 잘 안 보일 수 있다. 문제는 그 사각형 **밖**
(원거리 외삽, `DL_BEV_FAR_LIMIT_M`)이다 — 원근 왜곡·카메라 마운트 각도·피치
변화가 커지는 원거리일수록 "PPM이 똑같이 맞는다"는 보장이 없다. **그래서 이
도구는 여러 거리에서 반복 측정해서 거리별로 오차가 커지는 추이를 보는 용도로
설계했다** — 한 거리에서 한 번만 재고 끝내면 이 도구를 만든 의미가 없다.

## 도구가 하는 일

- 길이를 아는 물체(줄자로 정확히 잰 막대/테이프, 기본 1.0m 가정)의 양 끝점을
  카메라 BEV 화면에서 클릭한다(한 샘플에 두 번 클릭).
- 현재 `DL_PIXELS_PER_METER` 가정으로 계산한 두 점 사이 거리(측정거리)를 실측
  줄자 거리와 비교해서 **보정배율**(`실측거리/측정거리`)을 계산한다.
- `--samples`(기본 3)회 반복 — 매번 다른 거리에 놓고 재도록 안내한다.
- 마지막에 샘플별 보정배율, 전체 평균/표준편차, 제안 `DL_PIXELS_PER_METER`
  값과 config.py에 붙여넣을 코드를 출력한다. 표준편차가 크면(거리별로 배율이
  다르면) "PPM 상수 하나로는 다 못 고친다"는 경고도 띄운다.

## 사용법

```bash
python3 tools/measure_pixels_per_meter.py
# 실측 물체 길이가 1m가 아니면
python3 tools/measure_pixels_per_meter.py --known-distance-m 0.5
# 반복 횟수(=측정할 거리 개수)를 늘리면 거리별 추이를 더 잘 볼 수 있음
python3 tools/measure_pixels_per_meter.py --samples 5
```

실행 흐름: 샘플마다 "이 샘플을 대략 몇 m 지점에 놓았는지"(기록용, 생략 가능) 입력
→ 카메라 창에서 끝점 A 클릭+확정 → 창이 다시 뜨면 끝점 B 클릭+확정 → 다음 샘플로.
**첫 샘플은 가까운 곳(BEV 캘리브레이션 범위 안, ~1m 이내)부터, 그 다음은 점점 먼
곳에** 놓고 반복하는 걸 권장한다.

## 출력 예시 (가상)

```
=== 결과 ===
        ~0.5m: 측정거리=0.502m  보정배율=0.996
        ~1.5m: 측정거리=1.612m  보정배율=0.930
        ~2.5m: 측정거리=2.910m  보정배율=0.859

보정배율 평균=0.928 (표준편차=0.069)
★주의★ 샘플 간 보정배율 표준편차가 5% 넘게 큽니다 — 거리별로 오차가
        다르다는 뜻(원거리 외삽 취약성, README §2.30/§2.2)일 가능성이 높습니다.

현재 DL_PIXELS_PER_METER = 200.0
제안 DL_PIXELS_PER_METER = 185.6  (= 현재값 × 보정배율 평균)
```

(위 숫자는 "원거리일수록 보정배율이 작아진다 = 실제보다 더 넓게 보고 있다"는
가상의 예시일 뿐, 실측 전이라 실제 경향은 다를 수 있다.)

## 알려진 한계 / 다음 단계

- 표준편차가 크게 나오면(원거리 외삽 취약성이 실제로 확인되면), 이 도구가 출력하는
  "제안 PPM 하나"는 근거리/원거리 어느 한쪽에도 완벽히 안 맞는 절충값일 뿐이다 —
  그 경우 상수 하나로 고치는 대신 거리 구간별로 다른 값을 쓰거나, 이 근본적
  한계를 문서에만 남기고 넘어가는 것도 선택지.
- 이 값을 실제로 `config.py`에 반영하면 `DL_DA_VEHICLE_MARGIN_M` 침식 반경,
  `PASS_OFFSET`, `PP_WHEELBASE_PX` 등 `DL_PIXELS_PER_METER`를 참조하는 다른
  상수들의 픽셀 환산도 전부 같이 바뀐다 — 반영 전 어디서 쓰이는지 한 번 더 확인할 것
  (`grep -n DL_PIXELS_PER_METER track_drive/track_drive/*.py`).
- 4순위(선택)라 다른 세 개(라이다 n, 라이다-카메라 오프셋, IMU 부호) 확인이 먼저
  끝나지 않아도 독립적으로 진행 가능.
