# `measure_lidar_camera_offset.py` — 라이다-카메라 BEV 오프셋 실측 도구

2026-08-14 세션 요약. 코드 자체의 상세 설계 배경/알려진 한계는 `README.md` §2.30에도
기록돼 있음 — 이 문서는 "이 도구가 왜 필요했고, 어떻게 쓰고, 어떤 버그를 거쳐왔는지"를
빠르게 훑기 위한 요약본.

## 왜 필요한가

실차에서 "B2(고정장애물)/B3(방해차량) 회피 중 차량 앞코가 장애물 뒷꽁지를 긁고
지나간다"는 보고가 나왔다. 원인을 짚어보니:

- `_largest_da_component()`/`_da_slice_centers_windowed()`(`perception/dl_lane.py`)가
  da 중심선을 뽑을 때 **차량 폭을 전혀 고려하지 않는다** — 차량을 폭 0인 점으로 취급.
- 대응책으로 "da 마스크를 차폭만큼 침식(erosion)"하는 안을 검토했으나,
  `DL_PIXELS_PER_METER=200px/m`가 config.py에 **"설계값(실측 아님)"**이라고 명시돼
  있다는 걸 확인 — 가감속에 따른 피치 변화, 원거리 외삽, 카메라 마운트/진동에 취약해서
  "몇 cm 여유"를 카메라 픽셀 계산만으로 보장하기 어렵다는 결론.
- 대신 **라이다(실측 거리/폭, m 단위)를 카메라 BEV 좌표계에 투영**해서 그 자리만 da에서
  깎아내는 쪽으로 방향을 잡았다 — da(카메라)는 "모양", 라이다는 "정확한 거리/크기"를
  담당하는 역할분담.
- 근데 이걸 하려면 **라이다 원점 ↔ 카메라 BEV 원점 사이의 평행이동 오프셋**이 필요한데,
  지금까지 실측된 건 `LIDAR_ANGLE_OFFSET_DEG=80.0`(각도/회전 보정, README §6.2,
  2026-07-22)뿐이고 **평행이동 오프셋은 한 번도 실측된 적이 없었다** — 이 도구는 그
  오프셋을 실측하기 위해 만들었다.

## 도구가 하는 일

- **ROS2 빌드/노드 없이 `python3 measure_lidar_camera_offset.py`로 바로 실행.**
  `track_drive` 패키지를 import하지 않음 — 필요한 상수(`DL_BEV_SRC_PX_RAW`,
  `DL_PIXELS_PER_METER`, `LIDAR_ANGLE_OFFSET_DEG`)는 config.py에서 그대로 복사해왔다
  (★config.py 값이 바뀌면 이 파일도 같이 갱신할 것★).
- **카메라**: `cv2.VideoCapture`로 직접 열어(`usb_cam_node_exe` 안 거침) `dl_lane.py`와
  동일한 BEV 호모그래피를 재현. 물체의 바닥점을 클릭하면 `(forward_m, lateral_m)`이
  화면에 뜬다.
- **라이다**: `rclpy`가 있고 `/scan`이 발행 중이면(라이다 드라이버 노드만 떠 있으면 됨,
  `track_drive` 전체 launch 불필요) 정면 부채꼴 안 최근접점을 자동으로 잡고, 없으면
  `ros2 topic echo /scan`으로 읽은 `(range, index)`를 입력하는 수동 모드로 폴백한다.
- 여러 샘플(기본 3회, 물체를 좌/중앙/우로 옮겨가며) 반복 측정 → 평균/표준편차와 함께
  `config.py`에 바로 붙여넣을 `LIDAR_TO_CAM_DX_M`/`DY_M` 코드 블록을 출력한다.

## 사용법 요약

1. 라이다 드라이버만 띄운다(`track_drive` 전체 launch 불필요).
2. `python3 measure_lidar_camera_offset.py` 실행.
3. 물체(상자 등)를 **차량 앞범퍼에서 0.3~0.8m 전방, 차선(보라색 사다리꼴) 사이**에
   놓는다 — 첫 샘플은 **정면 중앙**부터(라이다 y, 카메라 lateral 둘 다 0 근처로 나와야
   정상이라는 sanity check가 됨).
4. 카메라 창에서 물체의 **바닥에 닿는 지점**을 클릭 → 화면에 `forward/lateral` 미리보기가
   뜨면 **카메라 창에 포커스를 준 상태에서 Enter 또는 Space를 눌러 확정**(그냥 클릭만으로는
   안 넘어감 — 잘못 찍었을 때 다시 클릭해서 고칠 수 있게 확정 단계를 따로 둠).
5. 라이다 값은 자동(rclpy) 또는 수동 입력으로 이어서 받는다.
6. `--samples`(기본 3)회 반복 후 최종 오프셋과 config.py 붙여넣기 코드가 출력된다.

## 이번 세션에서 발견/수정한 버그 3건

실차에서 처음 돌려보면서 연달아 발견된 버그들 — 전부 카메라 캡처 쪽 문제였다.

| # | 증상 | 원인 | 수정 | 커밋 |
|---|---|---|---|---|
| 1 | ROI 노란 박스/보라 사다리꼴이 트랙이 아니라 **천장 쪽**을 가리킴 | `cv2.VideoCapture()`를 해상도 지정 없이 열어서 드라이버 기본 해상도(640x480보다 훨씬 큼)로 열렸는데, 오버레이 좌표는 640x480 기준 고정값이었음 | `CAP_PROP_FRAME_WIDTH/HEIGHT`로 640x480 요청 + 실패 시 강제 리사이즈 | `46d44a9` |
| 2 | 보라색 사다리꼴이 **실제 차선보다 넓어 보임** | 위 수정이 단순 `cv2.resize(640,480)`라 원본이 4:3이 아니면(예: 16:9) 가로/세로가 다른 비율로 눌려서(왜곡) 실제 트랙 폭이 좁아 보임 | 리사이즈 전에 **가운데를 4:3으로 crop**해서 종횡비 왜곡 방지(`_to_640x480()`) | `f14efc3` |
| 3 | 바닥점을 클릭해도 **다음 단계로 안 넘어감** | 클릭=미리보기, Enter/Space=확정인 2단계 UX였는데 안내가 터미널에만 짧게 있고 화면엔 없었음 | 화면 상단/클릭 후 하단에 확정 안내 오버레이 추가 + Enter 키코드(13/10) 폭넓게 인식 | `f2fad52` |

## 알려진 한계 / 다음 단계

- 이 도구는 **오프셋 실측까지만** 한다 — 실측한 `LIDAR_TO_CAM_DX_M`/`DY_M`을 실제로
  `dl_lane.py`에서 라이다 장애물 상자를 da 마스크에 투영해 깎는 로직은 아직 없다.
  → **다음 단계**: 실차에서 이 도구로 오프셋 실측 → `config.py`에 반영 → da 클리핑
  로직 구현.
- 라이다 y(좌+)와 카메라 lateral(우+) 부호 관례가 서로 반대 — 오프셋을 실제로 합성해
  쓸 때 부호를 다시 한번 명시적으로 확인해야 함.
- 버그#2의 4:3 center-crop은 근사치다 — `usb_cam_node_exe`가 실제로 잡는 640x480
  모드와 광학적으로 100% 동일하다는 보장은 없음. 화면에서 보라 사다리꼴이 실제
  차선폭과 육안으로 비슷해 보이는지 재확인 필요. 여전히 안 맞으면
  `v4l2-ctl --list-formats-ext -d /dev/video0`로 640x480이 실제 네이티브 지원
  모드인지 확인하고, 지원한다면 crop/resize 근사 대신 그 모드를 직접 강제하는 쪽으로
  다시 고칠 것.
- `rclpy` 자동 라이다 모드는 이 개발 환경(ROS2 툴체인 없음)에서 실행/검증이 불가능해
  실차에서 처음 돌려봐야 한다 — 수동 입력 폴백 경로는 항상 동작하도록 만들어뒀다.
