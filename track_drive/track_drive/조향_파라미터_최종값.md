# 조향 파라미터 최종값 (시뮬레이션 결과 정리)

`pp_tune_gridsearch.py`(화이트박스 합성 시뮬레이션, Optuna TPE)로 찾은 Pure Pursuit +
코너감속 파라미터를 속도별로 정리한 표. **실제로 `config.py`의 `PP_TUNE_PRESETS`에 이
값들이 그대로 들어가 있고, 현재 활성 프리셋은 `speed15`**다(`PP_TUNE_ACTIVE_PRESET`).

전체 진행 과정/근거/실차 테스트 기록은 [새로운_조향테스트.md](새로운_조향테스트.md) 참고 —
이 문서는 그중 "최종적으로 config.py에 반영된 값"만 빠르게 찾아보기 위한 요약본이다.

---

## ⚠️ 실차 미검증 — 사용 전 반드시 확인할 것

- 전부 **화이트박스 합성 시뮬레이션 결과**다. 세그멘테이션 노이즈(1.5px, 가정값)/트랙
  곡률(도면 실측이지만 지그재그 회전각은 가정)에 의존하므로 실차와 다를 수 있다.
- **`PP_WHEELBASE_PX`(전 속도 48.8~50.0)**: 과거 47.36이었다가 "좌우 진동"으로 25.0
  으로 되돌려진 이력이 있는 값과 같은 구간. 최우선 확인 대상.
- **`SPEED_ACCEL_STEP`(전 속도 1.08~1.58)**: 과거 1.014로 LVC(배터리) 트립이 재현된
  구간과 겹친다. 시뮬레이터가 배터리 전류를 모델링 안 해서 점수로는 안 걸러진다.
- **`SPEED_CORNER_MIN`**: speed10/12.5/15는 그리드서치 원값이 `SPEED_NORMAL`보다
  커서(코너감속 무력화 버그) `SPEED_NORMAL*0.7`로 수동 보정된 값이다(아래 표는 보정 후).
- **`ANGLE_RATE_MAX`(조향 변화율 제한, 12도/틱)가 반영되기 전에 나온 값**이다 —
  급커브/지그재그 전환 구간에서 시뮬이 가정한 조향 반응이 실제 서보보다 빠를 수 있다.
  (반영 작업 진행 중, 새로운_조향테스트.md 다음 단계 참고)
- 실차 첫 테스트에서 **속도가 계속 5로 고정되는 현상이 관찰됨 — 원인은 이 파라미터들과
  무관하게 `SPEED_AVOID_HOLD_BLOCKED`(장애물 회피, 라이다 전방 감지) + `ll_bands:0/8`
  (차선 라인 인식 완전 실패)로 확인됨.** 조향 파라미터를 바꿔도 이 문제 자체는 안 풀림 —
  새로운_조향테스트.md 참고.

**물리 상수**: `METERS_PER_SPEED_UNIT = 0.0848` (실측 3점 5~10~15 원점고정 회귀 — **20
이상에는 이 상수를 쓰지 말 것**, 견인력 손실로 비선형 구간 진입 추정).

재확인 필요.

`PATH_EMA_ALPHA`는 현재 config.py 값(0.25)의 약 2~3배 — 전 속도가 일관되게 더 높은
값을 원함(스무딩을 덜 하라는 뜻). 노이즈 실측(`NOISE_STD_PX` 검증) 전까지는 이 방향을
확정하지 말 것 — 실제 노이즈가 가정(1.5px)보다 크면 반대 방향이 맞을 수 있음.

## 사용법

`config.py`의 `PP_TUNE_ACTIVE_PRESET`을 아래 중 하나로 바꾸고 colcon build:

```python
PP_TUNE_ACTIVE_PRESET = 'speed15'   # None / 'speed10' / 'speed12_5' / 'speed15' /
                                     # 'speed17_5' / 'speed20' / 'speed22_5' / 'speed25'
```

`None`으로 두면 프리셋 없이 `config.py` 개별 값(위쪽 정의) 그대로 사용.
