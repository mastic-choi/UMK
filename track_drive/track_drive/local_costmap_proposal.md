# 로컬 코스트맵(카메라+라이다 융합, 시간축 기억) — 계획 (착수 예정 2026-08-17)

**상태: 계획 단계, 코드 미착수. 착수 예정일 2026-08-17.** `teb_local_planner`(ROS,
Timed Elastic Band) 조사 중 나온 논의를 정리한 문서 — TEB 전체(그래프 최적화,
homotopy class 병렬 탐색)를 그대로 들여오는 건 우리 스택(지도/오도메트리 없음)엔
비현실적이지만, TEB가 전제로 깔고 가는 **로컬 코스트맵**(장애물 정보를 시간에 걸쳐
기억하는 그리드) 하나만 떼어서 만드는 건 지금 상황에 맞는 다음 단계라는 결론.

## 왜 이게 필요한가

이번 세션에서 avoid-hold(§2.32/§2.33), da 연속성 보조트리거(§2.33 적용2),
disparity extension 아이디어(`disparity_extension_margin_proposal.md`)를 각각
따로 패치했는데, 다시 보면 셋 다 **"카메라/라이다가 그 순간만 보고 기억을 못
한다"는 하나의 근본 문제의 서로 다른 증상**이었다:

- avoid-hold: 장애물이 화면에서 사라지면 da가 즉시 원래 폭으로 돌아옴 → 타이머
  하나로 "방금까지 있었다"를 억지로 기억시킴.
- da_area_jump: "방금까지 뚫려있던 구멍이 메워짐"을 감지하려고 직전 프레임 면적을
  따로 저장.
- disparity extension: 장애물 자리에만 안전마진을 걸고 싶은데, 그 자리를 매 프레임
  라이다→카메라로 다시 투영해야 함.

로컬 코스트맵(장애물 위치를 시간에 걸쳐 들고 있는 자료구조 하나)이 있으면 이 셋이
전부 자연스럽게 공짜로 해결된다 — 각 증상마다 임시 변수를 따로 만드는 대신, 하나의
공유 그리드로 통일. `Nav2 STVL`(맨 처음 avoid-hold 리서치에서 인용)과 이번 TEB
논의가 독립적으로 같은 결론(시공간 decay 기반 코스트맵)에 도달했다는 것도 이 방향의
근거.

**중요**: TEB의 핵심 가치(그래프 최적화, homotopy class 병렬 탐색)는 안 가져온다 —
코스트맵은 순수 **인지(perception) 레이어**고, 그 위에서 도는 건 지금 쓰는
`_da_slice_centers_windowed()`/Pure Pursuit을 그대로 둔다. 입력만 raw da 대신
"카메라+라이다가 합쳐지고 최근 몇 초는 기억되는 그리드"로 바뀌는 정도.

| 값 | 실측치 | 비고 |

## 착수 전 선행 작업 (우선순위 순)

**[2026-08-15] 아래 네 항목 전부 자동 실측 도구가 `tools/`에 준비돼 있다** — 각
도구의 사용법은 짝 `.md` 문서 참고.

**1순위 — 라이다 인덱스↔각도 공식 버그 수정 (프로덕션 코드, 아직 미수정)**
`measure_lidar_camera_offset.md`에서 이미 발견된 버그: 라이다가 실제론 한 바퀴에
**500포인트**를 찍는데, `perc_obstacle()`/`perc_lavacon_trigger()`는 여전히
**360으로 가정**한 옛 공식(`deg = index*(360/m) - 80`, `m=min(n,360)`)을 쓴다.
정면에서 멀어질수록(=다른 각도의 장애물일수록) 위치가 틀어진다 — 코스트맵에 라이다
좌표를 찍기 전에 반드시 고쳐야 함. `measure_lidar_camera_offset.py`의
`_index_to_deg()`(`(i - 정면인덱스) * (360/n)`)는 이미 고쳐져 있으니, 같은 방식을
`track_drive.py` 프로덕션 코드로 옮기면 됨 — 단, 실차에서 `n`이 항상 500인지 먼저
확인. → **`tools/measure_lidar_scan_count.py`**(신규)가 이 `n` 확인을 자동화한다
(라이다 구독만 하는 순수 읽기 도구, 클릭/입력 불필요).

**2순위 — 라이다-카메라 평행이동 오프셋 실측 (`LIDAR_TO_CAM_DX_M`/`DY_M`, 미실측)**
카메라 da 좌표계와 라이다 좌표계를 하나의 그리드에 합치려면 둘의 원점이 차체에서
얼마나 떨어져 있는지 알아야 하는데 **지금까지 한 번도 실측된 적 없음**(각도 보정만
있었지 평행이동은 없었음). → **`tools/measure_lidar_camera_offset.py`**가 이미 이
도구로 만들어져 있으니, 1순위(각도 공식)를 고친 뒤 이 도구를 실차에서 끝까지
돌리기만 하면 됨.

**3순위 — IMU 요레이트 부호규약 확인 (실차 미검증)**
그리드를 "차가 이동한 만큼" 밀어주려면(자기위치 추정) 조향 방향과 IMU z축 각속도
부호가 맞는지 알아야 하는데, README §0.5.5에 "z축 +가 좌/우 중 어느 쪽인지 실차
미검증"이라고 명시돼 있음 — 지금까지는 `abs()`로만 써서 문제없었지만, 코스트맵은
방향까지 정확히 알아야 해서 이번에 처음 확인 필요. `v_mps`는 VESC 실측이라 그대로
씀. → **`tools/measure_imu_yaw_sign.py`**(신규)가 좌/우로 번갈아 돌리며 부호를
확인하는 절차를 자동화한다(차량을 손으로 들고 돌리기만 하면 됨, 트랙 주행 불필요).

**4순위(선택, 없어도 착수는 가능) — `DL_PIXELS_PER_METER` 재검증**
"설계값(실측 아님)"이 config.py 전체에서 반복 지적됨 — 카메라 쪽 셀의 미터 환산이
근사치라 정확한 라이다 셀과 약간 어긋날 수 있음. 없어도 코스트맵 자체는 만들 수
있음(다른 기능들도 다 이 근사치 위에서 이미 동작 중) — 여유 있을 때 재검증. →
**`tools/measure_pixels_per_meter.py`**(신규)가 여러 거리에서 실측 길이와 BEV
계산값을 비교해 보정배율을 자동 계산한다(거리별 추이까지 보여줘서 원거리 외삽
취약성이 실제로 있는지도 같이 확인 가능).
